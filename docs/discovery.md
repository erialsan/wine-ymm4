# 発見記録: プレビュー全黒の真因は「コマンドリスト内の Clear」

## 症状

Wine 上で YMM4 が起動・編集・音声合成・タイムラインまで全部動くのに、
**プレビューも動画出力も全フレーム真っ黒**（Direct2D の描画が画面に届かない）。

## 調査手法（要点）

1. **d2d1.dll に fprintf 直書きのトレースを大量に仕込む**
   （Wine の `WINEDEBUG` はデフォルトで FIXME/ERR を抑制するため、`fprintf(stderr,...)` で直接出力する）
2. フレーム構造を全て記録: `SetTarget` / `BeginDraw` / `EndDraw` / `DrawImage` /
   コマンドリストの録音・再生 / `Clear` / エフェクトグラフの再帰
3. **キャンバス（D2Dターゲット）の実画素をダンプ**: ステージングテクスチャに
   `CopyResource` → `Map` して平均RGBを計算し、「実際に何が描かれているか」を数値で確認

## 決定的だった比較

| フェーズ | キャンバスの実測値 |
|---|---|
| エクスポート実行中 | `(113,79,75)` = 写真正色（正しい） |
| プレビュー再生中 | `(0,0,0)` = 完全な黒 |

同じパイプラインなのに再生だけ黒 → 再生固有の余分な操作を追跡:

```
[再生フレーム] Clear(黒) → CL再生 → Clear(透明) → 葉描画 → CL再生 → Clear(透明) → EndDraw
                                                    ↑ ここで描画された内容を
[エクスポート] Clear(透明) → CL再生 → 葉描画 → EndDraw    最後の Clear が全消去
```

## 真因

YMM4 はフレーム末尾に**「Clear（透明）だけを記録したコマンドリスト」**を再生する。

- **本物の Windows Direct2D**: コマンドリストへの Clear は実行されない（無効化される）ため実害なし
- **Wine の d2d1**: 律儀に記録し、リプレイ時に**実際に実行**する
  → 毎フレーム最後にキャンバスが全ワイプ → プレビュー・書き出しが真っ黒

## 修正

`d2d1_device_context_Clear` のコマンドリスト分岐で **record せず return** する
（パッチ `0003-d2d1-Don-t-record-Clear-into-command-lists.patch`）。
これだけでプレビュー・書き出しの両方が正しく描画されるようになった。

## 検証（修正後）

- プレビュー窓キャプチャ: 写真が中央に正しい色で表示（mean 74 / 赤プローブ 0.0）
- エクスポートmp4: フレーム抽出で写真正色・アーティファクトなし
