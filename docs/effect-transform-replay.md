# アイテムの X / Y / 拡大率がプレビュー・書き出しに反映されない件（2026-10-19 修正）

## 症状
YMM4 v4.56.1.1 で、ImageItem の `X`（例: 300px）が右パネルには `300.0 px` と表示されるのに、
**プレビューも書き出した mp4 も常に中央（X=0）で描画される**。
不透明度・拡大率も同様に反映されない（Length 変更だけは反映される）。

## 計測方法
`dlls/d2d1/device.c` に `YMM4DIAG` 環境変数で有効になる診断出力を仕込み、
`YMM4DIAG=1` で起動して描画コマンド列を記録した（本リポジトリのパッチには診断出力は含めていない）。

## 原因

アイテム 1 個の描画は次の順で流れる:

```
effect {e8467b04-…} (3DTransform)   4x4 .41 = 300.000        ← X=300 はここに載っている
transform applied
SetTransform (1,0,0,1,1260,540) target_type=1   ← 中央(960,540) + 300 が CTM に載る
effect {6aa97485-…} (2DAffine)      恒等行列
SetTransform (1,0,0,1,1260,540)
SetTransform (1,0,0,1,960,540)                  ← ★ ここで 300 が消える
DrawImage img=<アイテムのコマンドリスト> off=(-640,-360) ctxT=(1,0,0,1,960,540)
DBfill d=(-640,-360,640,360) s=(0,0,1280,720)   ← 結果は中央
```

`d2d_command_sink_SetTransform()` は、コマンドリストに**記録された絶対変換**（このアプリでは恒等行列）に
`replay_offset`（= `DrawImage()` に渡された `target_offset` = 960,540）を足して `SetTransform` する。

そのため、効果（2DAffine / 3DTransform）の行列を **レンダーターゲットの CTM** として設定しても、
その内側のコマンドリストをリプレイした瞬間に CTM が `recorded + replay_offset` で**上書き**され、
効果行列の平行移動が失われる。

実機の Direct2D は効果を「入力画像を中間サーフェスに描画 → その結果に行列を掛けて合成」するので
この現象は起きない。CTM で代用していた近似が壊れていたのが真因。

## 修正
効果行列を CTM だけでなく**リプレイ合成にも載せる**。

- `d2d1_private.h`: `unsigned int effect_matrix_valid; D2D1_MATRIX_3X2_F effect_matrix;` を追加
- `device.c` の効果チェーン近似部: 効果行列 `m` を `effect_matrix` に保存。
  ネスト時は **外側 ∘ 内側**（外側が内側の結果に掛かる）で合成し、再帰から戻ったら復元
- `d2d_command_sink_SetTransform()`: `applied = effect_matrix · recorded`、その後
  `replay_offset` を加算して `SetTransform`

ビットマップ相手の直接描画は従来どおり `SetTransform(combined)` を通る（コマンドリスト経路では
シンク側が上書きするので二重適用にはならない）。

## 検証（実測値）

プレビューの実測は子ウィンドウ（636x358, 1920 幅 → スケール 0.33125）、書き出しは mp4 のフレームを
ffmpeg で抽出して写真（高彩度ピクセル）の bbox 中心を求めた。

| 条件 | プレビュー | 書き出し mp4 (1920x1080) |
|---|---|---|
| 修正前 X=300 | オフセット **-0.5px**（中央のまま） | オフセット **-0.5px**（中央のまま） |
| 修正後 X=300 | オフセット **+98.5px**（= 297.4 project px） | オフセット **+299.5px** |
| 修正後 X=484.5 | 左端が +61px（184.5 × 0.33125 = 61.1 と一致） | — |
| 修正後 X=0 | オフセット **-0.5px**（中央） | — |

右パネルの X スライダーをドラッグするとプレビューが即座に追従することも確認（ライブ反映）。

- 実行時検証は **wine 11.18 ツリー**（`dlls/d2d1` を `make -C dlls/d2d1 -j8` でビルドし、
  `/opt/wine11up/lib/wine/x86_64-windows/d2d1.dll` と プレフィックスの `system32/` に配布）で実施。
- wine 11.20 向けは `patches/d2d1/wine-11.20-d2d1-ymm4-complete.patch` を再生成済み。
  素の wine-11.20 ツリーに `git apply --check` が通り、`dlls/d2d1/x86_64-windows/device.o`
  が警告なしでコンパイルできることを確認。

## 関連して分かったこと（未解決ではないもの）

- **プレビューにアイテムの選択枠が出ない**: d2d1 への描画要求が **0 件**
  （コマンドシンクの `DrawRectangle` 呼び出しなし）、親ウィンドウ側のオーバーレイも無い
  （プレビュー子ウィンドウの取得画像と親ウィンドウの該当領域が完全一致）。
  → Wine の描画バグではなく、アプリが要求していない。
- **`Ctrl+S` の保存は書き込み可能なプレフィックスなら成功**する（保存後にファイル内容と mtime が更新）。
  読み取り専用プレフィックスでは `AppData` への書き込みで `UnauthorizedAccessException` になる。
- `wineserver -k` で強制終了すると次回起動時に
  「異常終了を検知しました。バックアップからプロジェクトを復元しますか？」が出る。`いいえ(N)` で通常起動。
